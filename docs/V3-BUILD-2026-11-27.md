## 1. NEW FINDING — R3-FREE-NEWROOT (demonstrated, closed by this revision)

While mapping the v3 circuit changes we found that **`newMerkleRoot` is a FREE
witness input in every pool circuit generation** — `circuits/pool.circom`,
`circuits/pool3.circom`, and therefore every deployed pool (gate3, gate6, gate6b,
mainnet-pusd-pool, nito v2/v4, role-2 v1/v2, the 3-out pool). Verified at three
levels:

1. **Circuit**: `newMerkleRoot` appears ONLY as a witness input wired into the
   actionHash (`pool3.circom:106,214,230`) — there is no append/update template
   anywhere in the circuit (`grep -n "append|UpdateTree" circuits/*.circom` → the
   only hits are comments).
2. **Hook**: the 11-check role-2 hook writes the carrier's `newRoot` into the new
   state NFT commitment (check 10) and anchors the proof to the STORED root
   (check 5) — but nothing recomputes the append (`ROLE2-POOL-HOOK-DESIGN.md` §5).
3. **Client scan**: the nito.cash scan enforces root *continuity*
   (`scan.js:170-173`, `prevRoot === proven n0`) and NEVER recomputes the
   3-leaf append — a planted root passes it untouched.

**The drain (two ordinary proofs, evidence bar identical to the R2 doubling
probes):** action A "plant" is an honest TRANSFER whose `newMerkleRoot` is the
root of a FAKE tree (the real leaves + the action's own three commitments + two
fabricated notes, one of value = the pool's ENTIRE balance). Action B "drain" is
an UNSHIELD whose two in-notes are the fabricated notes, with membership proofs
against the planted root. **Both proofs verify against the DEPLOYED 3-out VK**
(snarkjs `groth16 verify` OK; evidence
`/home/apecs/cov/role2-probe-freeroot-drain-3out.json`, apecsdev VM; the probe
is committed at `pusd-shielded-pool/spike-nullset/probe-freeroot-drain.mjs`).
NOT broadcast. No nullifier reuse is involved — **this drain is independent of
and simpler than R2-NULLIFIER-DOUBLING, and the nullifier SMT alone does NOT
stop it** (a fabricated note's nullifier is fresh). The standing rule (no valued
asset in any current-hook pool) already covers it.

**The fix (in this circuit revision):** the append is now PROVEN in-circuit —
three sequential `DenseAppend` dual-walk inserts chain
`merkleRoot -(cm0)-> r1 -(cm1)-> r2 -(cm2)-> newMerkleRoot` (§3.2). The
negative gate (`spike-nullset/probe-v3-negatives.mjs`): the R3 plant witness is
now REJECTED at `wtns check` (the append chain fires), while the honest control
passes.

## 3. The circuit (`pusd-shielded-pool/circuits/pool4.circom`, measured)

### 3.1 The deposit path (onboarding — the design-doc v3 piece)

`isDeposit` (private witness flag, boolean-constrained):

- gates BOTH in-note membership checks: `(1 − isDeposit)·(inMerkle[i].root − merkleRoot) === 0`
- pins both in-note values to zero: `isDeposit · inValue[i] === 0`
- the phantom in-notes' secrets are witness-chosen; their nullifiers ride the
  carrier as usual (fresh SMT slot claims — producing a REAL note's nullifier
  requires its private nk/rho, so pre-claiming is not an attack)
- conservation is unchanged (`sumIn + signedPublic === sumOut` ⇒ deposit:
  `sumOut = pv`), and the hook's balance arithmetic + BCH consensus token
  conservation enforce the deposited value exactly as for a shield
- **the bootstrap-seed dependency is GONE**: the v3 pool's genesis tree is
  EMPTY (`zh[20]`), and the first notes enter via a deposit. Validated at
  genesis by `wtns check` (witness `/tmp/w-deposit.json`, VM).

### 3.2 The append proof (R3 fix) — `circuits/noteappend.circom`

`DenseAppend(D)`: the spike's dual-walk insert (SMTInsert), adapted:

- variable leaf (the commitment `cm[k]`, not a constant marker),
- the **dense-shape rule**: `IsEqual(siblings[i], zh[i]).out === 1 − keyBits[i]`
  — every level's sibling is the zero-hash `zh[i]` exactly when the slot's bit
  is 0. Together with the 0-walk (the zero leaf folds to the current root) this
  pins each insert to the tree's true FRONTIER slot: a witness cannot append
  into a hole (a slot beyond the fill count has an empty left neighbor at the
  first differing height, violating the rule), so the on-chain tree stays
  dense and client-reconstructible (the nito scan appends sequentially — a
  holey tree would fork every honest client).
- the Poseidon zero ladder is HARDCODED (20 constants) — computing it
  in-circuit would cost 20 extra Poseidon(2) per instance; the witness
  generator asserts the constants match its own ladder at runtime
  (`role2-op-witness-v3.mjs`, `CIRCUIT_ZH` check).

Three inserts chain the roots (circom requires each component's inputs set
before its outputs are read — the inserts are wired in sequence).

### 3.3 nf0 ≠ nf1 (R2 fix at the proof level)

`IsZero(nf[0] − nf[1]).out === 0`. The demonstrated doubling loaded one recorded
note as both in-notes; that witness now dies at `wtns check` (line 190 =
the IsZero constraint). The hook-level SMT remains the cross-ACTION replay
defense (the in-circuit check cannot see prior actions) — both are required.

## 4. The hook-level nullifier SMT (script side — the spike's decision)

Depth 254, SHA256, keyed by the carrier's proof-bound nf slices
(actionHash fields 0/1 — NO actionHash change). Per action, TWO nullifier-data
inputs (raw-script-locked, ~8.2-KB sibling witnesses each, self-funding
budgets `(41+8,481)×800 ≈ 6.8M` vs ~1.25M-op walks):

```
 input 2 (state NFT, role 2)        input 3 "walkA"              input 4 "walkB"
 ┌────────────────────────┐         ┌─────────────────────┐      ┌─────────────────────┐
 │ commitment:            │  read    │ 0-walk(nf0): zeros  │ read │ 0-walk(nf1): zeros  │
 │   [0..32]  noteRoot ──┼────────► │   fold == state's   │      │   fold == midRoot   │
 │   [32..64] nullSetRoot ┼─read──► │   nullSetRoot ✓     │      │   (from INPUTBYTE-  │
 │                        │         │ 1-walk(nf0): new    │      │    CODE(3)) ✓       │
 │ out1 (new state):     │         │   root == midRoot   │      │ 1-walk(nf1): new   │
 │   [0..32]  newRoot ───┼─hook     │   (midRoot pinned   │      │   root == out1's    │
 │   [32..64] finalNull ─┼─checked  │   in walkA's own    │      │   commitment[32..64]│
 │                        │  by 2/3 │   unlocking)       │      │   ✓ (pinned)       │
 └────────────────────────┘  inputs │ sibs: 254×32 B      │      │ sibs: 254×32 B     │
                                   └─────────────────────┘      └─────────────────────┘
```

- **walkA** (input 3): reads the state's `nullSetRoot` (UTXOTOKENCOMMITMENT(2)
  split), the carrier's nf0 slice (OUTPUTBYTECODE(0)); 0-walk folds the 32-zero
  leaf up its 254 siblings and must equal `nullSetRoot` (non-membership);
  1-walk (leaf = the 32-B spent marker) emits `midRoot`, pinned to a declared
  32-B field at offset 0 of walkA's OWN unlocking.
- **walkB** (input 4): reads `midRoot` from input 3's unlocking
  (`OP_INPUTBYTECODE(3)` — same-tx atomicity makes the shared surface sound);
  walks nf1 the same way; the final root must equal the new state NFT
  commitment's second half (OUTTOKCOMMIT(1)[32..64]).
- **Role 2** (input 2, the hook): checks the new state commitment's FIRST half
  (== carrier newRoot) and the 64-B length; the SECOND half is pinned by walkB.
  The old fold check 7 (`newNull = SHA256(old‖nf0‖nf1)`) is REMOVED — it was
  the broken mechanism.
- The two nullifier-data inputs are **raw-script outputs** (locking = the walk
  script itself, ~4-6 KB loop form — the redeem does NOT ride the unlocking,
  keeping each unlocking ≈ 8.2 KB under the 10,000-B cap; the spike's measured
  unrolled walk was 11,656 B > cap at D=254, hence the function/loop form).
  They are permissionless to create (anyone can pre-fund them; the walks are
  self-validating against the state) — the lock tx just embeds the fixed
  deployed lockings.
- Replays die at the 0-walk (a spent nullifier's slot is non-empty → the zero
  leaf no longer folds to the root); `nf0 == nf1` dies at walkB (nf0's slot is
  filled in midRoot) AND in-circuit.
- Genesis: `nullSetRoot` = the empty SHA256 SMT root (the 254-level zero fold,
  computed by the witness tooling).

The JS mirror + walk-data generation (sibsA/midRoot/sibsB/finalNullRoot, with
4/4 walk cross-checks) is built into `role2-op-witness-v3.mjs` and emitted in
every op JSON (`nullSet` field) for the action builder.
