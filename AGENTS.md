### Architecture facts (verified from design docs + handoff)
- Circuit: BN254 Groth16, 2-in/2-out joinsplit with dummy-note padding; 183,472 constraints (`build256/pool.r1cs` on runner). Exactly 2 public inputs `[merkleRoot, actionHash]`; `actionHash = Bits2Num(253)(SHA256(nf0|nf1|cm0|cm1|publicValueAbs|publicValueSign|assetCategory|newMerkleRoot))` (32-byte BE fields, 253-bit truncation). `assetCategory` is a PRIVATE witness (two 128-bit limbs `assetCategoryHi/Lo`) — the same compiled circuit + verifying key work for ANY CashToken category.
- Discrepancy note: `CIRCUIT-DESIGN.md` describes the earlier 7-public-input plan with `assetCategory` pinned as a public input; the shipped Option B design packs everything into `actionHash` (2 public inputs). Treat `GENERALIZED-SHIELDING.md` + the handoff as current.
- In-circuit hashing is Poseidon (~hundreds of constraints/hash); SHA256 (~25k constraints/hash) would blow up the circuit. The on-chain side never re-hashes the tree.
- Covenant: `asset-pool.cash` → `contract AssetPool(bytes32 assetCategory)`; the category is a CONSTRUCTOR PARAM — the **347-byte redeem** (measured on-chain from transfer tx `b0a488db…` input 0, 2026-11-01; supersedes the handoff's "222-byte" figure) is identical for every asset. ~66k op-cost (~2.5× under budget). State `{merkleRoot, nullifierSet}` carried in a mutable CashToken NFT commitment. Spend requires the Groth16 verifier tx as sibling inputs (6-input/7-output single-tx shape per pool op).
- On-chain verifier: `densless-msm` from `mr-zwets/zk-verifier-bench` wired to the pool VK; 35,626 B in ONE standard transaction; proven on BCH 2026 VM — 5/5 valid proofs accepted, 9/9 mutated public inputs rejected, 26/26 red-team runs rejected. `vk_x` is recomputed in-script, never accepted as a witness. BCH 2026 op-cost budget is per-input: `(41 + unlockingLen) × 800`, max ≈ 8,032,800.
- Upstream fix: `mr-zwets/groth16_cashscript` PR #26 (author `nyusternie`) — red-team push round-trip (OP_1NEGATE/OP_1..OP_16) — **MERGED 2026-10-30T14:21:57Z**, merge commit `3af2ad8c67d715a583690ab7728e1c8b8ad76a76` (verified via GitHub API 2026-11-01). Regenerating the red-team no longer needs `artifacts/redteam.mjs.patched`; pull the merged upstream.
- Proof reuse rule: a Groth16 proof is bound only to (verifying key, public inputs) — not to address/txid/fee. Reusable across redeployments with the same VK + tree state. Double-spend protection lives in the on-chain nullifier set; stale roots block replay. Never rely on proof "freshness."
